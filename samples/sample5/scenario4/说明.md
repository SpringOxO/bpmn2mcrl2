# Sample4 单实体验证说明

本目录包含两个单独实体的 BPMN 模型：

- `bpmn/Transport.bpmn`
- `bpmn/Freight-Forward.bpmn`

验证脚本会把这两个 BPMN 文件转换为 mCRL2，并检查每个单独实体是否可以成功生成 LPS 和 LTS。

## 执行命令

在仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File samples\sample4\verify_entities.ps1
```

该命令会执行完整流程：

1. 将 BPMN 转换为 mCRL2。
2. 执行 `mcrl22lps` 生成 LPS。
3. 执行 `lps2lts` 生成 LTS。
4. 如果本机存在 `ltsinfo`，输出状态空间统计信息。

如果只想检查转换和 LPS 生成，不生成 LTS，可以执行：

```powershell
powershell -ExecutionPolicy Bypass -File samples\sample4\verify_entities.ps1 -SkipLts
```

生成文件会写入 `samples/sample4/mcrl2/`。

## Environment 支持方式

这两个单独实体 BPMN 使用 `Environment` participant 表示所有外部参与方。有些 message flow 直接连接到整个泳池，而不是连接到具体的 BPMN task 或 event。

转换器对这种 participant 级别的消息端点做了补偿：为每条相关 message flow 生成一个很小的外部进程。

- 如果 message flow 从 participant 出发，并指向实体内部节点，转换器会生成一个外部发送进程：

  ```mcrl2
  env_send_<flow_id>(oid: OrderId) = s_<message>(oid) . delta;
  ```

- 如果 message flow 从实体内部节点出发，并指向 participant，转换器会生成一个外部接收进程：

  ```mcrl2
  env_recv_<flow_id>(oid: OrderId) = r_<message>(oid) . delta;
  ```

这些生成的 Environment 进程会被加入 `init` 的并发组合中。这样实体侧的发送或接收动作就可以通过已有通信规则完成同步：

```mcrl2
s_<message> | r_<message> -> c_<message>
```

这是一个轻量级 Environment 模型。它的作用是让单独实体验证时通信闭合，避免因为缺少外部对端而死锁。它不建模完整业务协议，也不验证完整多参与方流程。
